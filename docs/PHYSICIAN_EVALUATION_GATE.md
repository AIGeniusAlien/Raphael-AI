# Physician evaluation engineering gate (synthetic cases only)

This gate consumes the **actual** output of `python -m dev_verify --all --require-browser --output /private/verification`. It does not execute tests itself, authenticate reviewers, verify report provenance, inspect a deployment, certify model performance, or grant permission to use real patient data.

Run `python -m scripts.physician_evaluation_gate /private/verification/results.json`. A nonzero exit code and `BLOCKED` status mean the required engineering evidence is missing or failed. `ENGINEERING_GATE_PASS` means only that the supplied report lists passing required engineering checks. Because JSON reports can be copied or edited, an operator must independently confirm the report belongs to the exact source commit and test environment being evaluated; this script is not a tamper-resistant attestation.

Before a physician session, a qualified coordinator must separately confirm the actual application URL/build and source commit, use exclusively synthetic or properly authorized de-identified cases, verify clinician account isolation, document each participant's role and consent, and prepare an incident/escalation contact. No generated diagnosis, treatment, triage or imaging interpretation may be used for clinical care. Participants should explicitly record factual errors, missing evidence, unsupported certainty, workflow failures, unsafe recommendations, privacy/access-control failures, and usability concerns. Stop evaluation if isolation, authorization, or safety controls fail.

A successful supervised evaluation is **not** a clinical pilot or production authorization. Real clinical activation requires intended-use and regulatory assessment, independent specialty-specific validation on representative data, privacy/security and institutional approval, model-change governance, and operational incident response. The November 7 release report lists additional outstanding gates. Do not infer that these are satisfied by this script.
