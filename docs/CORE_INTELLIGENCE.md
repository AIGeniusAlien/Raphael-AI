# Core intelligence workspace

Sign in to the synthetic portal as a clinician and open **Clinical conversations and active notes**. The patient chart link passes the authorized patient ID; a new conversation can instead select general research. Context is fixed for an existing thread. Use **New conversation/change patient** to select another context. Patients and administrators are denied this clinician workspace API.

## Conversations
Create a named thread, ask a question and watch actual OpenAI-compatible streamed deltas. Configure LLM_BASE_URL,LLM_API_KEY and LLM_MODEL using secure environment settings. No runtime fixture provider is installed. HTTPS is required; loopback HTTP is allowed only with explicit RAPHAEL_ALLOW_LOCAL_LLM=1 for approved local tests/development. Approved local SQLite evidence is retrieved before the model call; absent evidence abstains without a provider call. The server checks that returned bracket citation IDs belong to retrieved excerpts. This is source-ID membership,not factuality or medical validation. Tokens stay provisional. Errors become failed drafts,not successful answers. Stop uses both authenticated cancellation and browser abort; backend closes the provider iterator when processing resumes,subject to the provider timeout. Regenerate resends the prior question as a new recorded generation. History,model name,generation IDs and statuses persist; JSON export is available. Safe headings/lists and structured assessment rendering use text nodes,never model HTML. Existing structured assessment uses the schema/critic pipeline; select RAPHAEL_EVIDENCE_BACKEND=sqlite for local reviewed excerpts or configure Qdrant.

## Recording and documentation
Select a synthetic patient,create/open an encounter,confirm authorization/recording consent and start documentation. The browser requests microphone permission only after an explicit Enable microphone action. Speech recognition is supported only where the browser exposes SpeechRecognition/webkitSpeechRecognition. Browser-vendor recognition may transmit audio to that vendor; the UI discloses this before consent. This is not an OpenAI realtime connection or clinically validated transcription. No audio recorder or undisclosed background upload is implemented. Browser speech activity callbacks drive listening indicators.

Standard mode places recognized final text into the composer for review. Hands-Free mode requires explicit activation and a configured wake phrase; matching final utterances initiate the clinician draft request. Pause/mute,stop and a two-minute timeout stop recognition; speech synthesis can read completed drafts and can be interrupted. Late permission grants and retired-recognizer callbacks cannot restart or contaminate a later session. Real microphone/vendor accuracy is unverified; controller tests use labeled fixtures. Manual synthetic transcript entry is separately labeled and works without speech services.

Final transcript segments persist with their declared source. SOAP/progress drafts are explicit deterministic templates:reported text,not independently observed,not assessed,pending clinician review. They never invent clinical findings. Additional segments create versions until a clinician edit is present; those edits require explicit merging and cannot be overwritten by automatic template updates. Optimistic versions reject stale saves/approval. Approval is explicit,immutable and audited; it publishes the approved content into the existing patient notes view. It is a synthetic signoff workflow,not verified clinician licensure/legal electronic signature. Session IDs allow authorized resume after reload; audit and version history are visible. Consent revocation rejects further transcript segments.

## Known gaps
No real microphone/provider speech evaluation,OpenAI realtime audio,diarization,AI clinical note synthesis,chat attachment intake,calibrated diagnostic confidence or independent source support/clinical validation is claimed. Existing chart documents,messaging,DICOM and FHIR routes remain unchanged. Live LLM_BASE_URL/LLM_API_KEY and QDRANT_URL were unset during this execution. Automated provider calls used an explicitly labeled local HTTP fixture or mock transport,not a live medical model.
