# Feature inventory and reconciliation gap analysis

This inventory distinguishes active code, historical implementations, partial scaffolds, synthetic/local test evidence and the complete product requirement. The canonical requirement IDs and acceptance criteria are in REQUIREMENTS_MATRIX.md. The full vision is not complete. No unprovided conversation history was accessed.

## Evidence inspected

- Current tracked Python, JavaScript, HTML, configuration, dependency manifests, tests and documentation under the checkout, including optional Playwright/Chromium E2E; placeholder and demo files were counted as artifacts rather than functioning features.
- Owner's original master directive retained in RAPHAEL_MASTER_SPEC.md and the new expanded reconciliation directive supplied with this task.
- Locally available Git history from initial `ec3274d` through the recovery branch. The inventory includes features formerly present in historical `main.py` and later removed. Historical code was read, not executed against live services or data.
- Original prototype API documentation, pilot guide, SaMD skeleton, evaluation cases, extension popup and Electron UI are sources of requirements even where current routes are missing.

## Complete-platform gap summary

The complete Raphael vision includes independently validated patient and physician portals, authorized two-way messaging with consent and delivery semantics, evidence/source quality and licensing, longitudinal patient intelligence, validated diagnostic and treatment support, multimodal imaging/voice/time-series, interoperable EHR/PACS workflows and operational/regulatory controls. The current development application implements only a bounded subset. Notable absent areas include registration/account recovery/identity proofing, comprehensive chart data, caregiver/consent models, real notification/delivery services, lab/medication/dosing safety databases, verified clinical source corpus, image/voice models, PostgreSQL migrations, disaster recovery, independent security review, clinical benchmarks and regulatory assessment. All remain in the matrix even where a helper or historical prototype once existed.

The synthetic release cannot satisfy clinical release gates. Clinical notes and AI messages are drafts until clinician review; internal stored messages cannot be represented as external delivery. No live-service success or HIPAA/FDA readiness can be inferred from the code inventory.
