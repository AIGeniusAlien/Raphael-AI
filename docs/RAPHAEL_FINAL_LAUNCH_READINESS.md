## Implemented and integrated

1. **Claim-screen protocol v2.** Each generated paragraph has one fixed response key. Strict provider schemas restrict quote choices to that paragraph's cited sources and prohibit contradictory classification/verdict shapes. Independent Python validation still requires exact source spans, complete coverage, all-reference support, population applicability, at least one supported claim and no unsupported/uncertain claims. Malformed output fails closed with static diagnostic codes. No threshold, clinician-review boundary, timeout or retry count was relaxed.
2. **Truthful live acceptance.** The harness always enables claim screening. Blocked/failed responses and absent screens cannot be counted as completed supported workflows. Real physician and patient workflows complete, retain citations and match freshly fetched CDC sources. Two tests cover the acceptance contract; they are not themselves live-provider proof.
3. **Longitudinal review.** The existing authorized chart now shows dated provenance and exact-unit/source numeric comparisons. Same-time conflicting observations block comparisons. Future/draft observations are excluded from arithmetic. Values are not converted, diagnosed or given causal explanations. Existing chart records and controls remain available. Four actual Chromium layouts were captured and visually inspected; mobile hierarchy was improved after inspection.
4. **Bounded generation context with durable provenance.** Clinician full-chart conversations select whole non-draft/past records from a bounded recent window, prioritize lexical question overlap and recency, and cap the selected context. IDs, revisions, source values, review flags and snapshot hashes persist per generation. Oversized context is omitted explicitly instead of slicing facts mid-JSON. Intake conversations retain only the authorized intake snapshot. Later chart edits do not mutate saved context; current owner/tenant/patient/consent authorization still controls access. The clinician UI exposes prepared snapshots. Preparation does not imply actual provider transmission or verified clinical findings.
5. **Reviewed observation extraction.** Authorized UTF-8 tabular .txt documents, at most64KiB/50rows, can be previewed for lab/vital observations. Wrong synthetic patient IDs, malformed/future/nonfinite rows, stale/tampered source hashes, unauthorized source access and duplicate label/time records are rejected. A clinician selects rows and explicitly approves publication into the chart. Imports are transactional, append-only and repeat-safe; original document/line hashes and parsed fields remain provenance. A later manual edit becomes a draft; retrying import does not reapprove it. Original document access and approved chart facts have separate permissions, disclosed before approval. This is not free-text, PDF, OCR, diagnostic extraction or independently verified patient matching.
6. **Private workflow checks.** A clinician can inspect outcomes and partial checker token usage for the last200owned generations that remain currently authorized. Responses contain no patient identifiers or text, send no external analytics and distinguish missing/blocked/passed screens from workflow completion. These protocol counts are not clinical-accuracy scores. Generation/embedding usage and complete monetary costs are not supplied.

Prior working features are preserved: encrypted authenticator MFA/recovery, memory-only native sessions, six structured paperwork workflows and seven transcript preparation formats, explicit clinician editing/approval/publication, consent controls, staged evidence versions/withdrawal/refresh planning, encrypted synthetic backup/restore and durable logout recovery.
