# Requirements traceability matrix

The master specification is a target, not a completion claim. IDs remain stable; append new IDs rather than renumbering. P0 = recovery/test-release gate, P1 = next platform work, P2 = later capability. `verified` is limited to the exact bounded description and tests named; `partial` means scaffolding or a narrower behavior exists; `missing` means no integrated implementation; `blocked` means a required prerequisite is unavailable; `untested` means code exists without validation. Mock results are not live or clinical validation.

Every feature bullet under master specification section 2 and every first-release acceptance criterion has a row. REC IDs track bounded recovery results separately so basic persistence does not imply a complete longitudinal patient system.
